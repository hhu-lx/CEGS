# 边际电价反馈改造设计

## 目标

在不新增电价策略、运行模式或配置文件的前提下，将现有“峰谷电价 + 单节点额外负荷线性加价”改为同时反映全网计算负荷和本节点计算负荷的归一化反馈价格。

## 保持不变

- 继续使用 `MarginalElectricityPricing`。
- 继续使用现有分时电价 CSV 作为共同价格底座。
- 保留现有构造参数 `base_price`、`sensitivity` 和 `scale`。
- 不增加网页选项、YAML 配置项或新的策略文件。

## 新计算方法

令 `P_i` 为某节点的数据中心额外负荷，`P_all` 为所有节点数据中心额外负荷之和，`S` 为现有 `scale`。价格改为：

`p_i(t) = p_TOU(t) * [1 + sensitivity * 0.5 * (max(0, P_all) / S + max(0, P_i) / S)]`

- 前半部分为系统负荷反馈；
- 后半部分为节点负荷反馈；
- 两项使用相同权重 0.5，不引入额外可调参数；
- `sensitivity=0.10`、`scale=1000 MW` 的现有默认值继续有效。

## 代码影响

- `src/strategies/electricity/marginal.py`：将加法电价改为基于峰谷底座的乘法反馈，并使其接收系统额外负荷。
- `src/infrastructure/pandapower_adapter.py`：在获取节点价格时汇总 `extra_loads` 并传入策略。
- 对固定分时电价模式、OPF 定价策略、接口名称、网页选项和既有配置格式不作改动。

## 实验含义

固定分时电价实验仍是无算电协同基线；启用边际模式时，所有中心共享同一分时电价底座，价格差仅来自系统与节点计算负荷反馈。这样可将传统基线与反馈协同实验分开报告。

## 验证

- 无额外计算负荷时，边际价格应严格等于该时段峰谷价。
- 增加任一节点负荷时，所有节点价格应因系统项上升，目标节点还应获得额外的节点项上升。
- 固定峰谷与 OPF 路径现有测试继续通过。
