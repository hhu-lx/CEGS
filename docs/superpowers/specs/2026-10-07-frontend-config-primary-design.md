# 前端上传配置主路径设计

## 背景

平台当前同时从 `config/platform.yaml` 和前端上传的用户配置读取数据中心等运行参数。仿真引擎会将用户配置合并到平台配置上，因此上传文件中的旧数据中心算力会覆盖项目配置中的新值。任务文件、电价文件也分别有独立上传入口和配置路径，增加了用户对“最终采用哪份数据”的判断成本。

## 目标

- 将前端上传的用户配置作为本次仿真的主要配置来源。
- 当上传配置未提供某一配置项时，使用 `config/platform.yaml` 的默认值。
- 让配置应用结果明确展示最终生效的数据中心算力及其来源。
- 移除用户配置文件中与专用任务/电价上传入口重复的数据文件路径。
- 不改变现有仿真调度、优化算法、设备功率曲线和带宽限制逻辑。

## 配置来源与优先级

1. `config/platform.yaml` 提供可运行的基础默认配置。
2. 本次前端提交的用户配置覆盖基础默认配置。对象型参数按字段合并；`data_centers` 与 `storages` 属于集合，上传其中任一集合时整组替换平台默认集合，集合项必须通过完整性校验。用户配置可包含数据中心、储能和仿真参数；未提供的段继续使用基础配置。
3. 前端专用任务文件上传是本次 Web 仿真的任务数据来源；任务文件路径不再通过用户配置中的 `tasks.excel_file` 或 `data_sources.task_file` 指定。
4. 前端专用峰谷电价 CSV 上传是本次 Web 仿真的电价数据来源；用户配置中的电价文件路径不再参与 Web 配置合并。
5. 电网时序文件、拓扑默认值及设备功率参考表仍由 `platform.yaml` 管理，不由前端用户配置重复指定。
6. 前端明确提供的调度策略、优化模式及上传文件优先于用户配置中对应的值；用户配置可继续提供前端没有独立控件的仿真参数和优化目标/权重。

此优先级只适用于 Web 配置提交。命令行配置入口的兼容行为需在实施计划中明确，避免无意改变现有 `--config` / `--user-config` 使用方式。

## 用户配置格式

更新 `config/user_config.example.json`，保留仿真参数、优化目标/权重、数据中心及储能配置，并将示例数据中心算力同步为当前建议值（DC1 250、DC2 200、DC3 300 TFLOPS）。移除用户配置中的任务/电价/电网时序/拓扑文件路径，避免与前端上传及平台默认配置重复。

Web 配置验证应拒绝或明确提示已弃用的重复路径字段，而不是静默接受后忽略，以便用户能及时修正旧配置。对于缺少数据中心或储能段的上传配置，使用平台默认值；提供这些段时，用户上传集合整体替换对应平台集合。对象型配置保留未覆盖的平台默认字段。

## 前端反馈

应用配置成功后，返回并显示最终有效的数据中心清单（名称、算力、带宽、GPU 设备数量）及来源：用户上传或平台默认。若上传文件中的算力覆盖了平台默认值，应明确显示覆盖后的值。仿真启动日志也应继续输出同一份最终配置，方便和前端展示核对。

## 迁移和兼容

- 更新配置模板及 README 的配置说明，描述“平台默认值 + 用户上传覆盖 + 专用文件上传”的职责边界。
- 对旧用户配置中重复的数据源路径给出可读校验提示。
- 不删除 `platform.yaml` 中的默认路径或平台资源配置；它们仍是未上传相应数据时的回退来源。
- 不删除前端用户配置上传入口；它仍是自定义数据中心、储能和仿真参数的主要入口。

## 验收标准

1. 无用户配置上传时，平台默认数据中心配置可正常加载。
2. 上传含自定义数据中心配置时，仿真实际使用上传值；未覆盖的字段保留平台默认值。
3. 上传旧版用户配置时，对重复路径字段给出明确错误或迁移提示，不静默造成错误来源。
4. 前端成功应用后显示最终生效的数据中心算力和配置来源，日志数值与页面一致。
5. 任务数据和电价仍分别通过各自的前端文件输入提交，不从用户配置路径二次读取。
6. 带宽值保持由有效配置提供，且本次整理不修改带宽调度约束。
