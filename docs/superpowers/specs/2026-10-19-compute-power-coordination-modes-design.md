# 算电协同三模式与电力侧优化设计

日期：2026-10-19

## 1. 目标

平台的三种实验模式都必须优化电力侧运行。常规机组、风电、光伏和储能在三种模式中始终参与；三种模式只通过算力侧与电力侧的耦合程度区分：

- 启发式：无算电协同；
- 局部优化：算力与电力分解求解并交替反馈；
- 全局优化：算力和电力变量在同一个模型中联合求解。

前端只能提供当前模式真正支持的选项。被模式固定或覆盖的选项必须禁用并显示原因，不能继续显示为“已应用”。

## 2. 统一边界与术语

### 2.1 算力侧变量

- 任务到数据中心的空间分配；
- 在任务最大等待时间内的开始时刻或延迟量；
- 数据中心计算、带宽和 GPU 资源占用；
- 数据中心功率，由已有预定义算力—功率映射计算。

### 2.2 电力侧变量

- 常规机组有功出力 `P_g`；
- 风电、光伏实际出力及弃风、弃光功率；
- 储能充电功率、放电功率及 SOC；
- 必要时的备用容量与带高惩罚系数的可行性松弛量。

### 2.3 共同约束

三种模式使用相同的电力物理约束和设备数据，避免实验差异来自不同约束集合：

1. 系统功率平衡；
2. 常规机组最小、最大出力；
3. 常规机组爬坡约束；
4. 风光实际出力不超过当前可用功率；
5. 储能充放电互斥、功率限制、SOC 上下限和时序平衡；
6. 数据中心计算、带宽与 GPU 资源约束；
7. 任务提交时间、处理时长和最长等待时间约束；
8. 电压与线路约束采用“线性模型求解 + AC 潮流校验”的流程；
9. 正常运行不得依赖松弛变量。只有无严格可行解时才启用松弛，并在结果与告警中明确标记。

系统功率平衡的统一定义为：

```text
常规机组 + 风电 + 光伏 + 储能放电 + 外部电网
= 基础负荷 + 数据中心负荷 + 储能充电 + 网络损耗
```

## 3. 三种模式

### 3.1 启发式：无协同基准

任务使用资源侧规则一次性分配：FCFS、资源可行性和负载均衡。任务分配不读取节点电价、碳强度、风光出力、电压、线路负载率或储能状态；已经分配的任务不因电力优化结果迁移或重新定时。

任务产生的数据中心负荷作为固定输入进入电力侧优化。电力侧独立优化常规机组、风光和储能，但不把求解结果反馈给任务调度器。

单个调度时刻的数据流为：

```text
任务到达 → 资源规则分配 → 固定数据中心负荷 → 电力侧优化 → AC 潮流校验
```

启发式模式不是“没有优化”，而是“电力侧优化存在、算电之间没有协调”。

### 3.2 局部优化：分解交替协同

局部优化将问题拆成算力子问题和电力子问题，在同一个调度时刻交替迭代：

1. 算力子问题根据当前节点价格、碳强度、时延和电网可承载信息选择任务位置与允许的执行时间；
2. 将形成的数据中心负荷交给电力子问题；
3. 电力子问题优化常规机组、风光和储能；
4. AC 潮流校验后更新节点价格、碳强度和拥塞信号；
5. 将信号反馈给算力子问题；
6. 当总目标相对变化不超过 `1e-3`，或任务分配连续两轮不变时收敛；最多执行 5 轮。

某一轮不可行时保留上一轮严格可行结果。若第一轮就不可行，则将任务保留在队列中，不以“约束违背最小”结果冒充可行解。

### 3.3 全局优化：统一联合求解

全局优化在一个模型中同时决定任务选址/时间、常规机组出力、风光出力和储能行为。独立调度策略不参与决策。

模型首先在滚动时间窗内求解联合 MILP/LP，应用第一个时段的决策，然后进行 AC 潮流校验。若 AC 校验失败，增加安全收紧约束后重求一次；仍失败则保持上一严格可行运行点，并将相关任务留在队列。

## 4. 时间尺度

仿真仍按秒推进，优化采用滚动时间窗：

- 任务释放、执行和资源占用使用秒级时间；
- 电力侧优化默认每 5 个仿真秒触发；
- 削峰填谷和 SOC 规划使用未来 24 小时的聚合预测窗口；
- 窗口内部默认按 1 小时离散，当前时刻执行第一段控制量；
- 数据不足 24 小时时使用现有数据循环补齐，并在导出结果中记录该数据策略。

此设计允许秒级任务实验继续运行，同时让储能具备跨时段规划能力。

## 5. 优化目标

### 5.1 电力侧目标

三种模式均支持：

- 最小运行成本；
- 最小碳排放；
- 最小弃风弃光；
- 削峰填谷；
- 综合加权目标；
- 自定义安全权重。

综合目标采用归一化分量：

```text
w_cost × 运行成本
+ w_carbon × 碳排放
+ w_peak × 净负荷峰谷差
+ w_curtailment × 弃风弃光量
+ w_storage × 储能损耗
+ w_delay × 任务时延
```

启发式模式下任务分配固定，因此 `w_delay` 不参与电力侧求解；前端不得提供“最小时延”作为启发式的独立优化目标。

### 5.2 社会福利命名

在未加入用户任务收益、发电收益和运营商收益前，页面与报告使用“综合加权目标”，不称为“社会福利最大化”。如后续加入效用函数，再单独扩展社会福利目标。

## 6. 机组数据

用户拓扑中的常规机组继续提供 `min_p_mw` 和 `max_p_mw`，并允许增加以下可选字段：

- `ramp_up_mw_per_hour`；
- `ramp_down_mw_per_hour`；
- `cost_linear_yuan_per_mwh`；
- `cost_quadratic_yuan_per_mw2h`；
- `emission_tco2_per_mwh`。

为了兼容现有 IEEE39 测试文件，缺失字段采用平台预定义的机组类型参数。默认爬坡能力取机组最大出力的 50%/h；默认成本和排放参数按拓扑节点的机组类型查表。导出结果必须注明哪些字段来自用户、哪些来自默认值。

基础发电时序不再直接覆盖每台机组的 `p_mw`。它改为以下用途：

- 作为总常规发电预测或参考轨迹；
- 为优化模型提供软约束/偏差惩罚；
- 优化结果成为最终机组出力。

## 7. 前端兼容矩阵与选择流程

优化模型是前端配置流程的上游选择。页面必须先让用户选择优化模型，再根据该模式动态展示仍然有效的调度策略、定价策略和优化目标，不能先展示全部选项再让后端静默覆盖。

配置区顺序调整为：

1. 任务文件；
2. 用户配置；
3. 峰谷电价文件；
4. 电力拓扑文件；
5. 优化模型；
6. 当前模型支持的任务调度策略；
7. 定价策略；
8. 当前模型支持的优化目标。

### 7.1 优化模式与控件

| 模式 | 调度策略区域 | 可选优化目标 |
|---|---|---|
| 启发式 | 不显示策略下拉框，显示只读项“非协同负载均衡（固定）” | 最小运行成本、最小碳排放、最小弃风弃光、削峰填谷、综合加权、自定义 |
| 局部优化 | 显示最低价格、低碳优先、延迟优先、负载均衡、自定义 | 全部电力目标及最小时延、综合加权、自定义 |
| 全局优化 | 不显示策略下拉框，显示只读项“由联合优化模型统一决策” | 全部电力目标及最小时延、综合加权、自定义 |

定价策略在三种模式下始终显示，因为它是电力侧优化和成本核算的有效输入。固定分时电价仍要求上传 CSV；边际电价和自定义电价沿用现有配置方式。

不兼容选项必须同时满足：

- 不出现在当前模式的可选下拉列表中；
- 固定行为使用只读说明卡代替禁用的下拉框；
- 切换模型时立即刷新策略、目标和自定义参数面板；
- 隐藏的自定义面板不得提交文件或页面参数；
- 提交时必须使用当前模式的规范化有效配置，不能提交上一次模式残留值；
- 切回原模式时可以恢复该模式下用户先前选择；
- 后端再次校验模式—策略—目标组合，绕过前端提交无效组合时返回 422，不能静默改写。

前端维护一张唯一的模式能力表，渲染、表单提交和提示文案均从该表读取，避免三处逻辑不一致。例如：

```text
heuristic:
  dispatch = fixed_load_balance
  objectives = cost, carbon, curtailment, peak_shaving, weighted, custom

local:
  dispatch = lowest_price, low_carbon, low_latency, load_balance, custom
  objectives = cost, carbon, curtailment, peak_shaving, delay, weighted, custom

global:
  dispatch = optimizer_managed
  objectives = cost, carbon, curtailment, peak_shaving, delay, weighted, custom
```

### 7.2 自定义目标

启发式模式保留成本、碳排放、削峰填谷、弃风弃光和储能损耗权重，禁用任务时延权重。局部与全局模式开放全部权重。

## 8. 软件结构

新增/调整职责如下：

1. `PowerDispatchOptimizer`
   - 构建常规机组、风光和储能的滚动电力优化模型；
   - 返回机组级出力、风光消纳、储能计划和目标分项。
2. `LocalCoordinationOptimizer`
   - 调用任务分配子问题与 `PowerDispatchOptimizer`；
   - 管理反馈信号、收敛判据和最大迭代次数。
3. `JointCoordinationOptimizer`
   - 在同一个模型中构造任务和电力变量；
   - 返回联合决策及目标分项。
4. `PandapowerAdapter`
   - 只负责应用优化结果、运行 AC 潮流和生成安全反馈；
   - 不再通过统一比例直接决定最终常规机组出力。
5. `SimulationEngine`
   - 根据模式调用三条明确的执行链；
   - 维护上一严格可行点和滚动窗口状态。

## 9. 结果与可观测性

每次优化结果至少保存：

- 模式、优化状态和迭代次数；
- 每台常规机组出力；
- 风电/光伏可用、消纳和弃电；
- 每套储能充放电、SOC 与损耗；
- 基础负荷、数据中心负荷、总发电和网络损耗；
- 成本、碳排放、峰谷差、弃电和时延目标分项；
- AC 潮流校验状态；
- 是否使用默认机组参数或可行性松弛。

前端实时图使用当前控制量，长时间尺度图使用聚合历史。导出文件保存完整时序，而不是只保存最新快照。

## 10. 测试与验收

### 10.1 单元测试

- 常规机组出力满足上下限和爬坡约束；
- 功率平衡成立；
- 风光实际出力不超过可用功率；
- 储能 SOC 时序守恒且不越界；
- 六种目标权重进入正确目标分项；
- 前端三种模式的禁用状态和提交值符合兼容矩阵。

### 10.2 模式测试

- 启发式的任务分配在改变电价、碳强度和风光数据后保持不变，但机组/储能/新能源结果可以变化；
- 局部优化至少完成一次算力—电力反馈，并在有限轮次内终止；
- 全局优化的任务与电力决策来自同一个模型；
- 三种模式使用同一组任务、负荷、风光和设备参数。

### 10.3 实验验收

对同一 24 小时场景运行三种模式，至少比较：

- 峰谷差和负荷方差；
- 风光消纳率和弃电量；
- 总运行成本；
- 碳排放；
- 任务完成率、平均等待时间和超时率；
- 优化耗时和局部迭代次数。

只有当三种模式都获得严格可行的 AC 潮流结果时，结果才进入论文对比表。

## 11. 兼容与迁移

- 现有任务、用户配置、电价 CSV 和拓扑上传接口保持不变；
- 旧拓扑缺失机组成本、排放和爬坡字段时使用明确记录的默认参数；
- 现有 `base_generation_pu` 文件继续可用，但语义由“直接缩放出力”改为“参考发电轨迹”；
- API 状态中保留旧统计字段，并新增机组级调度和目标分项字段；
- 前端先依据兼容矩阵阻止无效组合，再逐步展示新增电力优化结果。
